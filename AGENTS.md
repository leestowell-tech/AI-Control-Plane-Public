# Repository agent entry

This is a complete portable control plane, not an installed account or a grant of permissions. For a first installation with no established binding, follow [INSTALL](deployment/INSTALL.md) without inventing state or restarting an already completed account/connector setup. Once bound, read [BOOT](BOOT.md) and the relevant current methods. Use OPERATOR.md for the concise human interface and deployment/CAPABILITY_PROFILE.json for the full capability list.

Preserve the recipient’s entire goal, decisions, current grants, private state and domain ownership. Source-author approvals and personal policies do not transfer. Apply [Assurance](kernel/ASSURANCE.md), [Security/privacy](kernel/SECURITY_PRIVACY.md) and current recipient instructions. Read relevant current sources before consequential claims; distinguish instructions, execution, receiving and useful results.

For an ongoing installation follow deployment/INSTALL.md. Verify actual recipient ownership/access and host capabilities before effects. An existing GitHub account/connection is reused; do not repeat setup unnecessarily. Read-only source access does not establish a writable memory destination. Never write personal state to the original or a public fork. Preserve newest memory when reverting methods.

Perform useful work with the full methods and proportionate checks. Explain material failures, their impact and next valid action; do not hide them behind passing tests. Continue independent authorized work. No publication, spending, account/access changes, tool activation or automatic service follows from this file.

For repository maintenance run python3 tools/repository_hygiene.py generate and audit. These inspect structure, not account installation or model behavior. The maintainer retains source provenance; no private upstream repository is required at runtime. Preserve history and user changes; do not overwrite unique work or promote learning without its applicable authority.
