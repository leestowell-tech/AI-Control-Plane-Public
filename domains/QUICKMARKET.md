# QuickMarket Integration

Status: CURRENT INTEGRATION CONTRACT

QuickMarket is a specialist domain. Installing it does not give it authority over the whole control plane, and the control plane does not rewrite QuickMarket market doctrine.

## Integration
- Control plane owns cross-domain priority, user-level state, mission continuity, reset/recovery, and capture routing.
- QuickMarket owns market-specific doctrine, analysis/execution boundaries, local lineage, and volatile market-state requirements.
- Current market facts, prices, news, positions, broker state, and execution status must be refreshed from authoritative live sources when material; stored memory does not outrank them.

## Useful routed records
- user-stated investing preferences/objectives → user instance;
- market thesis/recommendation/outcome history → QuickMarket domain lineage/evidence;
- unresolved consequential market hypothesis → hypothesis record;
- generalized process lesson → learning candidate;
- live market data → do not promote to durable current truth merely by capture.

## Low-bandwidth behavior
The user may invoke QuickMarket normally. The control plane should silently handle recovery, source/currentness checks, capture routing, and mission continuity unless an actual decision or blocker requires attention.

## Safety boundary
Repository access alone never grants broker/trading authority. Any live execution permission must come from explicit live configuration and platform/broker constraints.
