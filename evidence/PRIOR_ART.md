# Prior Art and Provenance

Status: CURRENT EVIDENCE MAP

This repository adapts proven internal and external mechanisms; it does not claim that every rule is novel.

## Internal high-water mark
- COMMAND cognitive fabric / work-execution surface: typed Job Envelopes, Endpoint Descriptors, routing policy, workers, verification/reconciliation, and Routing Receipts; recommendation must be distinguished from dispatch and execution.
- COMMAND mission continuity: external objective representation, scope checksum, multi-lane continuity, typed blockers, handoff recovery.
- COMMAND owner-alignment/additive-default and repeated operator correction: a material build or upgrade must not silently collapse to a minimum patch; maximum coherent scope is the standing default when explicitly established.
- COMMAND full build protocol: discover/deep/challenge/converge/approve/execute/validate/observe/learn.
- COMMAND capture routing: current state, decisions, hypotheses, learning candidates, domain lineage, longitudinal context, no-capture.
- Atlas assurance and constitution: point-of-use grounding, provenance, no silent authority expansion/promotion, reversible evolution, proportional governance, human judgment preservation.
- Atlas learning lifecycle: observation/candidate/admission/promotion/demotion with contradiction and currentness controls.
- QuickMarket authority boundaries: volatile live state outranks repository memory; shared custody does not transfer execution authority.

## External high-water mark
- NASA software engineering / software assurance / IV&V: objective evidence, lifecycle assurance, independent verification, failure containment, validation versus verification, runtime/fallback concepts.
- NIST AI RMF and Generative AI Profile: govern/map/measure/manage, risk-proportional governance, testing/evaluation, provenance, incident handling, human oversight.
- Microsoft HAX Guidelines: clear capability boundaries, efficient invocation/recovery, granular feedback, global controls, explanations with automation-bias caution.
- Google PAIR Guidebook: user needs, mental models, feedback/control, error diagnosis, graceful failure.

## Provenance rule
Runtime kernel files should remain concise. When a rule is consequential or challenged, recover its derivation, evidence, scope, and currentness from this layer or linked primary sources rather than treating the short-form rule as self-justifying.
