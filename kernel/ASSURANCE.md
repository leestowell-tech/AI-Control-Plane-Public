# Assurance Kernel

Status: CURRENT

Treat AI failure as expected. Reliability belongs to the joint system: human, model, tools, sources, state, interfaces, validators, and governance.

## Core loop
`GROUND → SCOPE → PRODUCE → EVALUATE → ACT → VERIFY → PERSIST → MONITOR / LEARN`

## Rules
- Ground consequential current/durable claims from authoritative sources at point of use.
- Preserve the actual objective, selected scope mode, invariants, authority, non-goals, and return condition.
- Detect silent scope contraction: compare implemented and omitted surfaces against the approved scope and the predictable adjacent integrations identified during discovery.
- Treat AI output as candidate material until required evidence/gates are satisfied.
- Same-context self-critique is useful but not independent verification.
- Prefer deterministic logic when explicit rules solve the problem adequately.
- Bound action authority; stronger gates apply as consequence, irreversibility, privacy, financial impact, or semantic authority rises.
- Endpoint recommendation is not dispatch; dispatch is not acknowledgement; acknowledgement is not execution; tool success is not outcome truth; verify the receiving boundary when material.
- Persist durable changes in the correct system of record with enough provenance to recover.
- Revalidate when dependencies, models, data, or operating conditions change.

## Proportionality
Low-stakes work stays light. Stateful work requires current grounding. Consequential execution adds explicit scope, evidence, outcome verification, and stronger review. High-impact or irreversible work requires the strongest practical safeguards, fallback, and human approval where appropriate.

## Point-of-use and admission
For material state, durable decisions, execution, authority or changing external facts, retrieve the relevant current source in the same turn before relying on the claim. Earlier conversation/source retrieval is a discovery aid, not perpetual currentness. Stable low-stakes knowledge needs no ritual pull.
Check provenance, currentness, applicable scope, contradiction and allowed use. Historical authority labels do not establish present applicability. Keep fact, observation, inference, hypothesis, proposal and actual user decision distinct. Resolve conflicts or expose bounded uncertainty.
Routine work uses a lightweight source/outcome check; consequential execution adds explicit authority and receiver evidence; high-impact/irreversible work uses the strongest warranted verification and actual human gate. Same-agent/same-source repetition is not independence.

## Failed guards and direct statements
A failed or unverified safety/permission/receiving guard invalidates the dependent action: stop that action and enter an explicit blocked or supported fallback state. Do not repeat an unchanged failed action without new evidence. Continue independent authorized work. Only newly verified prerequisites and actual authority can reopen the held step.
A direct user statement can establish current intent or an attributed observation. It does not by itself verify external system state: “I choose printable” is a decision; “the upload must have worked” still requires receiver evidence before claiming delivery.
