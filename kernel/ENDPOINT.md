# Endpoint

Status: PORTABLE ADAPTATION / TARGET BEHAVIOR UNOBSERVED
Trigger: Endpoint Protocol or a clear request to examine a subject's mature destination. This is an analysis mode inside Build; invocation grants analysis and ordinary reversible custody, not new implementation authority.

1. Recover the subject, parent objective, values, horizons, current sources, prior endpoints, strongest relevant prior art, negative evidence, grants and holds. Keep owner intent, facts, hypotheses, forecasts and proposed authority distinct.
2. Describe observable successful maturity: normal operation, essential capabilities, human role, ownership/interfaces, resources/economics, resilience, independence and exit. Distinguish a finite completion milestone from enduring operation. Use meaningful near/mid/long horizons; never invent calendar promises.
3. Compare materially different successful forms, simpler repair/no-expansion, failure/exit and a stronger alternative with real added costs/permissions. Stress operator absence, resource limits, dependency changes and lack of demand. Bigger or more autonomous is not automatically better.
4. Work backward from maturity, then forward from actual capability. Distinguish controllable work, influenceable adoption and external dependencies. Preserve parallel valid lanes and source maturity; an experiment or document is not an installed capability.
5. For each material transition record condition/evidence, resulting action, owner, authority, cost/attention, verification, rollback/stop and return trigger. Consider preparation lead time. Unknown thresholds do not pass. A responsibility need not become a new tool/team/service.
6. Identify what should merge, disappear or remain separate as the system matures. Simplification cannot silently erase approved capability.
7. Deliver endpoint, current position, gaps, recommendation, next justified preparation/action and conditions that change the recommendation. For a real consequential decision use kernel/PACKET.md; valid existing execution grants remain active.
8. Save once in the existing owning mission/domain record, not a new planning system. Revisit on meaningful evidence, changed objectives or a named transition. No automatic watcher follows. Stop projection when remaining decision-critical uncertainties have concrete resolving owners/conditions and more speculation adds no value.
