# Reconciliation, upkeep and conditional action

Status: PORTABLE ADAPTATION / NO SCHEDULER INSTALLED BY THIS CONTRACT

## Full Update / Receipt Check
On explicit invocation or a material discrepancy during authorized work, recover the requested field from current state, active missions, domains and source/receiving records. Do not interpret Full Update as only editing a summary.
For each material change compare source production, durable custody, correct owner admission, discoverability, downstream use and actual outcome. A file/link/route is not evidence its consumer received it.
Reconcile old/current decisions, changed assumptions, stale derivatives, missing pointers, duplicate authority and unfinished independent lanes. Preserve unique history and the original scope. Repair obvious reversible source/state discrepancies within existing authority and verify readback.
Return actual changes and bounded unresolved items with their resolving owner/condition. Unknown coverage is not a clean bill of health. No artifact or failure is forced into a new system.

## Upgrade review
Use kernel/UPGRADE.md for explicit Upgrade Protocol, hardware reassessment or a stale/duplicated/value-negative mechanism. Hardware context considers the whole human/AI/software/hardware arrangement; a named narrower review retains its scope. Keep, add, reallocate, simplify/merge, replace and retire are real outcomes. Reuse the same work record and valid grants; detection creates no effect authority or permanent review queue.

## Activation and future work
For consequential conditional work record the actual condition, observer/event source, owning receiver, permitted next action, evidence/currentness, delivery route, failure response and closure. Valid routes can be event-triggered, a separately authorized periodic observer, or an explicit user invocation.
A written intention, stored trigger or prompt is not an installed observer. If the objective requires unattended detection, user memory is not an adequate substitute. Prepare a real bounded implementation through the existing endpoint; no background-running claim until uncued detection and receiving are evidenced.
Preserve NOT_DUE / TRIGGERED / CONSUMED / BLOCKED / STALE / SUPERSEDED / CLOSED when helpful. Silence is not evidence of health. Missing observer, source-read failure, missed event, failed action and failed delivery are different failures.

## Delivery and failure
An internal receipt does not prove the human saw it. Use active conversation for present decisions or a channel the user actually adopts for future attention. Do not import another user's morning schedule, SMS setup or checking habits.
For any authorized unattended action, bind condition → detection → evaluation → authority → effect → receipt → verification → useful delivery. Qualify duplicates, timeout/unknown effect, offline recovery, cancellation and missing-receipt escalation before claiming reliability. Read the receiver before retrying an ambiguous effect.
Future promises create no new schedule or message. Keep independently useful direct conversation operation when a runtime lane fails. Ask for added tools/cost/access only when the concrete requirement needs it.

## Continuous update
When ordinary work reveals a repeated failure, trace the existing chain from whole objective and current context through production, checking, receiving and user outcome. Repair the failed owner/interface within the grant, invalidate affected descendants and assess a subsequent applicable result. Retain the prior failure, valid controls, changed method, actual improvement or lack of it, rework and attention cost in the same work receipt. Do not count new rules, repeated attempts or additional measurements as benefit. Use kernel/LEARNING.md for the reusable procedure/candidate path; no parallel learning store is needed.

Apply deployment/UPDATES.md at boot/reset or a requested maintenance check when current sources are reachable. This is task-time discovery, not an unattended service. Record compatible receiving and actual limits; significant new authority remains a decision.
