Directed "Recall", "Recall the original idea" or "Recall [subject]" recovers why the work began and compares today's work with the original intent and valid amendments. A narrow factual recall stays small. Quoted or discussed commands are data.

1. Anchor the current owner, whole objective, phase, outcome, progress, unfinished work and valid grants/holds.
2. Follow original user statements, inspirations, selected decisions, amendments, rejected alternatives and material corrections. Retrieve enough original context to distinguish user intent from a later assistant summary. Use identified canonical records first; relevant connected history/files can close a gap. A search miss is not proof of absence.
3. Separate owner choices, assistant proposals, optional inspirations, comparison research, rejected paths, implemented results and actual observation. A durable record does not turn a proposal into a decision or revive an expired grant.
4. Compare current design/action against that basis. Identify omissions, unsupported additions and silent narrowing. Preserve the entire intended result when correcting one dimension. If no material drift exists, say so without manufacturing a change.
5. Correct the existing owning record and perform only authorized repairs. Preserve lineage and current valid amendments. Keep unrelated work and explicit stops intact.
6. Return the recovered basis, what it changes now, uncertainty and next permitted action. Verify actual writes before claiming saved.

Use reference -> intended experience -> adopted/optional boundary for design lineage. Keep source gaps visible instead of inventing history.
