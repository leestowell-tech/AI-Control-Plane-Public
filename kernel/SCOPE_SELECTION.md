# Scope Selection Kernel

Status: CURRENT

## Purpose
Prevent AI habit, local salience, cost anxiety, or “smallest thing that works” heuristics from silently shrinking a user’s actual objective.

This contract governs material architecture, infrastructure, governance, system creation, redesign, upgrades, and any task where a smaller-versus-larger choice would materially change delivered capability.

## Scope modes

### NARROW_REPAIR
A local defect correction with no justified load-bearing adjacent integration. Use only when the request is explicitly narrow or the defect boundary is demonstrably local.

### BOUNDED_SUFFICIENT
A defined outcome with a deliberately limited envelope. Use when the user explicitly requests an MVP, prototype, cost/time cap, or bounded first phase, or when a binding constraint requires it and is surfaced.

### MAXIMUM_COHERENT
The widest justified connected envelope needed to achieve the stated objective without predictable adjacent omissions, orphan interfaces, or “obvious in hindsight” missing machinery.

Maximum coherent is the standing default for material builds and upgrades. It is not “everything imaginable.” It remains bounded by:
- explicit objective and authority;
- evidence and actual capability;
- safety, privacy, irreversibility, and financial limits;
- declared non-goals and parked derivatives;
- maintainability, operator attention, and rollback;
- complexity that earns its place through a load-bearing relationship.

### UNBOUNDED_MAXIMAL
Pursuit of every conceivable extension. This is not a default and requires explicit user direction plus appropriate risk/cost gates.

## Precedence
1. Explicit current user scope direction.
2. Current approved mission envelope.
3. Demonstrated task shape and load-bearing integrations.
4. Standing default in this contract.
5. Model preference, convenience, token conservation, or implementation habit — never authoritative.

## Decision procedure
1. Restate the actual outcome, not merely the latest requested component.
2. Recover approved mission scope and prior corrections.
3. Enumerate the material scope alternatives.
4. Identify load-bearing adjacent integrations across intake/candidate coverage, authority/approval, data/provenance, interfaces/dispatch, failure/retry/cancellation, verification/acceptance, observability/recovery, and maintenance/drift/retirement/learning.
5. Choose the mode using precedence above.
6. Record mode, rationale, exclusions, and consequences in the Mission Ledger or equivalent durable record.
7. At convergence and closeout, compare delivered scope to the recorded mode.

## Mandatory ask rule
Ask before selecting a smaller mode when all are true:
- the difference would materially change capability, integration, future burden, or risk;
- current user direction and mission authority do not already decide it;
- the task is not clearly a narrow local repair.

The question must show the meaningful alternatives and consequences. Do not ask merely to offload ordinary design judgment.

## No-silent-minimum rules
- Implement, build, upgrade, improve, make robust, and equivalent requests do not imply minimum viable scope.
- Cost or quota awareness supports efficient routing; it does not authorize scope contraction.
- A local correction does not shrink the parent mission.
- Convergence removes unjustified complexity; it may not redefine maximum coherent as minimum.
- If a constraint prevents the selected scope, record a typed blocker or propose a phased plan. Do not quietly deliver less.
- Any material post-approval contraction is a scope change requiring evidence and authority.

## Phasing
Phasing is allowed when it preserves the complete approved envelope:
- the ledger retains all phases and their dispositions;
- phase one is not mislabeled as mission completion;
- dependencies and return triggers are explicit;
- later phases do not depend on the user remembering them.

## Acceptance
A scope decision passes only if:
- the mode is explicit;
- the objective and non-goals are preserved;
- predictable load-bearing integrations have dispositions;
- constraints and tradeoffs are visible;
- delivery can be reconciled against the original objective;
- the operator did not have to discover an omitted obvious integration after the fact.
